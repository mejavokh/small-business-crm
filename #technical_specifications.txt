	Проект: система автоматизации малого бизнеса

	Этап 1. Простая консольная CRM
Сначала без Django и Telegram.
Возможности
добавить клиента;
посмотреть клиентов;
изменить данные;
удалить клиента;
создать заявку;
поменять статус заявки;
найти клиента по имени или телефону.

Что изучишь
Python;
функции;
ООП;
модули;
исключения;
typing;
работа с файлами;
Git.
Сначала данные можно хранить в JSON. Затем заменить JSON на SQLite.
Срок: 1–2 недели.
  
	Этап 2. Нормальная база данных
Переносишь проект с JSON и SQLite на PostgreSQL.
Добавляешь сущности
пользователь;
клиент;
сотрудник;
услуга;
запись;
заявка;
оплата.

Что изучишь
PostgreSQL;
SQL;
связи между таблицами;
JOIN;
индексы;
транзакции;
SQLAlchemy;
Alembic;
миграции.
Срок: 2–3 недели.
 
	Этап 3. REST API на FastAPI
Теперь система работает через API.
Методы
POST   /clients
GET    /clients
GET    /clients/{id}
PATCH  /clients/{id}
DELETE /clients/{id}
Такие же методы создаёшь для сотрудников, услуг, записей и платежей.
Что изучишь
FastAPI;
Pydantic;
REST;
HTTP;
Swagger;
Dependency Injection;
async/await;
обработку ошибок;
архитектуру приложения.
Срок: 2–4 недели.
 
	Этап 4. Авторизация и права
Добавляешь регистрацию и вход.
Роли
владелец;
администратор;
сотрудник;
клиент.
Например, сотрудник видит только свои записи, а владелец — всю компанию.
Что изучишь
JWT;
OAuth2;
хеширование паролей;
permissions;
access token;
refresh token;
безопасность API.
Срок: 1–2 недели.
 
Этап 5. Административная панель на Django
FastAPI оставляешь основным API, а Django используешь для внутренней панели управления.
Через панель можно
управлять сотрудниками;
изменять услуги;
просматривать записи;
блокировать пользователей;
смотреть платежи;
видеть статистику.
Что изучишь
Django;
Django ORM;
Django Admin;
формы;
модели;
permissions;
интеграцию нескольких приложений.
Но на первом этапе необязательно сразу соединять Django и FastAPI. Можно сначала сделать отдельную версию проекта на Django, чтобы понять оба фреймворка.
Срок: 2–3 недели.

Этап 9. Оплата
Добавляешь оплату услуг или подписки.
Возможности
создать платёж;
проверить статус;
отменить платёж;
сохранить историю;
обработать webhook;
оформить подписку.
Для учебной версии сначала можно сделать фальшивую платёжную систему: пользователь нажимает «Оплатить», а специальный endpoint имитирует успешную или неуспешную оплату. После этого подключать настоящего провайдера.
Что изучишь
webhooks;
идемпотентность;
транзакции;
интеграцию внешних API;
безопасность платежей.
Срок: 1–2 недели.
